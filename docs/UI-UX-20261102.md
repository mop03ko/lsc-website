# UI/UX review — 2026-11-02

Scope: live MN/EN website, source review, desktop and browser-emulated mobile journeys. This is an expert review and functional QA, not a customer interview study; no conversion uplift is claimed.

## Findings and changes

- Discovery: the 3D catalog followed several long company/product sections. Move it directly after the hero and make model discovery the hero's main action, with budget estimation secondary.
- Expectations: six exterior models showed disabled floor/frame buttons without explanation. Show capability labels on cards and an explicit availability note; expose floor/frame controls only on the existing model with plan data. Respect the owner's decision to supply confirmed areas/drawings later.
- Selection: thumbnails appeared after the viewer, and mobile selection left the preview above the viewport. Present search/cards before the viewer, scroll the selected preview into view, and retain a visible selected-card border.
- Manipulation: zoom required gestures. Add labelled +/− and reset controls, keep camera-angle controls, and use 44px minimum control heights in the viewer.
- Recovery: zero search matches only changed a count. Add a readable empty state and a show-all button. Keep retry for failed model loads.
- Sharing: selections could not be linked. Support `?model=<id>#models` and copy-link with a visible fallback link if clipboard access is unavailable.
- Quotation: a previously selected calculator estimate could remain attached when requesting another model. Clear the estimate for a direct model request, and provide an explicit remove-estimate action.
- Estimation: explain that prices cover the frame/listed work, not a completed building; separate the indicative-rate note from the header grid and provide 40/80/120/200 m² presets.
- Small screens: compact hero metrics, scrollable mobile menu on short viewports, readable model cards, and constrain the viewer width to prevent 320px overflow.

## Reference basis

- W3C WCAG 2.2: https://www.w3.org/TR/WCAG22/ — target size and alternatives to dragging. 44px is our design target, not a claim that every WCAG criterion was audited.
- Nielsen Norman Group, Progressive Disclosure: https://www.nngroup.com/articles/progressive-disclosure/ — expose useful controls when their supporting data exists, with an explicit explanation for missing capabilities.

## Validation boundary

Run `npm run verify`; check MN and EN at 320, 390, 768, 1024 and 1440px; test empty-search recovery, direct model links, plan modes, zoom/reset, estimate presets/removal, and stale quote prevention. Local analytics requests can return 403 because the PHP preview lacks production origin configuration. Live verification must distinguish this preview limitation from production errors. No real customer form submission is used for UI testing.
